# ServoClock 串口通信与状态机学习复盘

## 一、目前的不足

1. **状态与事件容易混淆**：曾使用 `CommandMode` 同时管理工作状态和一次性命令，导致状态丢失或命令重复执行。
    
2. **边界检查不够全面**：出现过头文件中定义 `static` 状态变量、缓冲区长度不足、字符串处理缺少安全检查等问题。
    
3. **异常情况考虑不足**：例如未选中舵机就收到 PWM 命令、保存失败、错误帧未及时清除。
    
4. **模块职责尚不够清晰**：串口接收、协议解析、状态管理和舵机控制之间仍存在耦合。
    
5. **输入校验依赖发送端**：虽然当前 ±1、±10 调整配合限幅函数没有问题，但接收端尚未独立验证调整量是否合法。
    

## 二、提升方案

- **先设计状态机，再写代码**：明确 RUN、OFF、CALIBRATE_ON、CALIBRATE_OFF 的允许命令与状态转换。
    
- **加强 C 语言基础**：重点复习 `static`、`extern`、指针、整数类型、字符串和数组边界。
    
- **明确模块职责**：USART 负责接收，CommandParser 负责解析，App 负责状态，ServoRun 负责执行。
    
- **增强异常处理意识**：每个函数不仅考虑成功时怎么办，还要考虑失败时怎么办。
    

## 三、今后应该怎么做

1. 编码前先明确需求、协议格式及状态转换条件。
    
2. 一次只修改一个功能，不同时引入多个复杂改动。
    
3. 每次修改后测试正常、边界、异常三种情况。
    
4. 使用 Keil Watch 和测试帧确认真实执行结果。
    
5. 测试通过再提交 Git，并记录问题、原因与修复方法。
    

## 四、本次值得保持的习惯

你能够主动提出时间数据与模式命令分离的设计，也能根据实际业务需求纠正不合适的建议。这种独立判断值得保持。

**核心原则：先设计状态，再编写逻辑；先考虑异常，再确认功能完成。**
