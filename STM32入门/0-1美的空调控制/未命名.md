# 美的空调红外控制项目：完整调试复盘与智能红外收发器升级规划

> 整理日期：2026-10-21  
> 项目阶段：**STC89C52RC 红外控制实验已成功实机关闭空调；新一代 ESP32 智能红外收发器待开发**  
> 文档依据：本次聊天中的原理图、万用表结果、PulseView `.sr` 波形分析结论、交付工程与最终实机反馈。对未经验证的功能单独标记。

## 1. 项目目标及最终成果

最初的目标是使用一块已经完成打样的 STC89C52RC 开发板控制美的空调。开发过程从红外硬件搭建、载波调试、原装遥控器抓包开始，逐步定位发射强度与红外协议问题，最终完成了空调实际控制。

### 当前已经达成

- 使用 **STC89C52RC（8051）** 与 **11.0592MHz 晶振**产生约 **37.87kHz** 红外载波。
- 使用 **S8550（PNP）＋940nm 红外 LED＋限流电阻**组成发射电路。
- 使用 **VS1838B 红外接收头＋逻辑分析仪 PulseView**采集并解析原装遥控器波形。
- 识别出这台美的空调使用的 **B2 系列 48 位编码**（而非最初尝试的 A1 变体）。
- 成功复现原装遥控器的 ON/OFF 数据帧，并使空调**实际开机、最终顺利关机**。
- 构建了可按模式、温度、风速生成帧的 **v3.0 工程**。**除原装 ON/OFF 复现外，其他功能码尚需逐项实机验证。**

## 2. 第一版硬件

| 部分 | 实际选型 / 参数 |
|---|---|
| 主控 | STC89C52RC，Keil C51、STC-ISP |
| 晶振 | 11.0592MHz，12T 运行方式 |
| 红外载波引脚 | P1.0，Timer2 时钟输出 |
| 红外驱动 | S8550 PNP 三极管，基极 1kΩ，基极上拉 10kΩ（按当时外接原理） |
| 红外发射管 | F5 940nm 红外 LED，具体型号和辐射强度未知 |
| LED 串联限流 | 最初 5 个 1kΩ 并联＝200Ω；后来 10 个并联＝100Ω |
| 红外接收 | VS1838B，3.3V 供电，OUT 接逻辑分析仪 |
| 控制入口 | 串口 9600、8N1、ASCII 命令 |
| 主控电源 | 外接 5V；曾出现电源适配器异常发热，后续硬件应重新设计供电保护 |

### 电路曾遇到的异常

1. 电源开关 OFF 时板载 LED 仍微亮，ON 时变亮。排查发现 **S8550 基极相关的反向供电路径**；外接发射电路应与主板使用同一个**开关后的供电节点**，不要跨越电源开关反向供电。
2. 高强度发射测试阶段，外接 5V 电源曾异常发热，出现串口无法打开、暂时不能烧录与 P1.0 无波形；重新拔插恢复烧录和载波。**不能仅因后来恢复就认定电源异常的根因已经查清。**
3. 空闲时实测：P1.0≈5V、S8550 E≈5V、B≈5V、C≈0.87V、100Ω 两端≈0V，红外 LED 两端≈0.87V。结论是**没有发现明显的持续大电流**，但高阻状态和微弱漏电仍可能造成非零电压。

## 3. 调试时间线与关键结论

### 3.1 载波生成与发送驱动

- Timer2 复用 P1.0 输出约 **37.87kHz**；逻辑分析仪在 P1.0 与 S8550 集电极分别检测到约 **37.872kHz / 37.873kHz**。
- `TEST` 是约 100ms 的连续载波测试，不是完整遥控指令。VS1838B 有自动增益控制，对持续载波可能抑制，因此**不能只用 `TEST` 判定红外协议是否能被收到**。
- 发送完整 `HEAT 25` 时，最初的 A1 方案输出 `A18348FFFF55`、`5E7CB70000AA`（整帧反码），波形完整但空调不响应。

### 3.2 通过原装遥控器识别协议

采集 `空调ON_OFF.sr`，解析出：

| 行为 | 原装遥控器数据 | 发送方法 |
|---|---|---|
| OFF | `B2 4D 7B 84 E0 1F` | 同样 48 位帧重复 2 次 |
| ON | `B2 4D BF 40 D0 2F` | 状态帧重复 2 次 |
| ON 附加帧 | `D5 66 00 00 00 3B` | 上述两帧后追加 1 次 |

重要区别：**ON 与 OFF 不是同一条“切换”指令**，数据和帧数组合都不同。连续发送 `ON` 不会交替开关机。B2 状态帧中的字节按 `原字节、逐字节反码` 组织（如 `B2 4D`），不能误当成 A1 式整帧再取反。

### 3.3 对照手机、原装遥控器与自制发射器

- 原装遥控器与手机发送的 B2 指令内容一致，手机采样 `手机.sr` 共解码出 10/10 帧。
- 改版后 `红外发射.sr` 两次 OFF 都正确解码，之后的循环 ON 采样也多次解码成功。
- 原装与手机的解调脉冲宽度相近；自制发射器的数据载波脉冲经 VS1838B 解调后偏长。**这是接收端测得的波形差异，不能全部归咎于 MCU 定时，因为接收头 AGC 与光强也会影响它。**

### 3.4 发射距离与功率瓶颈

使用相同的 VS1838B 接收条件，在相同距离采集：

| 发射端限流 | 距离 | 完整正确帧 | 结论 |
|---|---:|---:|---|
| 200Ω | 30cm | 5/6 | 近距离基本可用 |
| 200Ω | 1m | 2/6 | 丢帧明显 |
| 200Ω | 2m | 0/6 | 已无法可靠识别 |
| 100Ω | 2m | 5/6 | 提高导通电流后显著改善 |
| 手机红外 | 2m | 10/10 | 在相同测试布置中明显更可靠 |

估算：5V 供电、LED 正向压降约 1.2V、驱动饱和压降约 0.2V 时，200Ω 的导通峰值电流约 18mA，100Ω 约 36mA。**仅知道 LED 是“F5 940nm”，不能确认允许的最大脉冲电流，不应无限降低电阻。**

### 3.5 电压与器件检查

- 红外 LED 二极管挡正向约 **1.048V**、反向 **OL**，符合正常单向导通现象。
- 200Ω 阶段 `TEST` 时 LED 两端约 **1.164V**，电阻两端约 **1.991V**。
- 100Ω 阶段循环发送时 LED 两端约 **1.356V**，电阻两端约 **2.207V**。由于是 38kHz 脉冲及多帧工作，**不能直接把万用表显示值作为导通峰值压降**。
- 静态检查及基极 / 集电极双通道波形曾再次确认开关动作存在，之后 VS1838B 对 ON 的录波可以成功解码 9/9 帧。

### 3.6 最终实机结果

- 在较远距离发射时空调最初无反应；提高发射能力并将发射管靠近后，空调开始发出与原装遥控器相同的提示音。
- 起初循环执行的是 `ir_b2_send_on_capture()`：这只会重复开机，不会触发关机。
- 后来单次发送 OFF 后，空调曾表现为停止出风、导风板未完全闭合、温度显示数字闪烁；这一表现不能单独证明 OFF 协议错误。
- **本次聊天最终由实机反馈确认“空调顺利关闭”**，表明当前 ON/OFF 红外控制方案已取得实际效果。

## 5. 最重要的工程经验

1. **先把物理层和协议层分开测：** MCU 载波正常 ≠ LED 光强足够；接收器能解码 ≠ 远距离一定可靠；空调响一声 ≠ 动作完全执行。
2. **建立对照基准：** 原装遥控器、手机、自制发射器在相同距离和同一接收头下比较，比主观观察手机摄像头紫光有效得多。
3. **重复发送与切换语义不是一回事：** 冷气开关通常使用明确的 ON/OFF 状态帧，而非一条简单 Toggle 指令。
4. **不要跨开关反向供电：** 功率驱动与主控的供电域设计要一致，防止 IO、三极管或外围模块意外供电。
5. **电源可靠性不能靠“能带三台舵机”推断：** 独立检查负载、电流、接线、适配器异常升温和 Wi-Fi 射频瞬态。
6. **协议可推导，但需要现场验证：** 模式、温度、风速、扫风应建立原装遥控器对照采样或实际设备验收表。

# 第二阶段：微型智能红外收发器（项目提案）

## 6. 产品定义

**定位：** 一个 USB-C 供电、可本地手机控制、可学习原装遥控器的微型智能红外控制器。第一版主要控制美的 B2 空调，之后扩展电视、风扇等红外设备。

**第一版验收目标（规划值，非已达成指标）：**

- 单板尽量控制在 **40 × 30mm 左右**（以布局及 USB-C、天线、IR LED 实际尺寸复核）。
- 单独 USB-C 5V 供电；没有额外的 8051 主控或 CH340 模块。
- 3～4m 正对目标空调稳定控制（明确在最终 PCB 和外壳下复测）。
- 接收、记录、重放原装 B2 红外码，并能通过手机 Web 页面触发。
- 初版支持 ON/OFF、温度、模式，后续增加风速、扫风、定时。
- 保留 USB 调试日志、BOOT / RESET 手段和必要测试点。

## 7. 推荐架构

```text
         手机（同一 Wi-Fi / 本地 Web App）
                       |
                   Wi-Fi 2.4G
                       |
             ESP32-C3-MINI-1
             /       |        \
       RMT TX      RMT RX     HTTP API / NVS
          |            |           |
   MOSFET 低边驱动   38k 接收头   遥控器码库/状态
          |
    高辐射 940nm IR LED

USB-C 5V ----+------ IR LED 供电支路
             |
             +-- 3.3V 稳压器 -- ESP32 / 接收头
```

**主控建议：** ESP32-C3-MINI-1-N4X（4MB Flash，一体 PCB 天线）。ESP32-C3 有 2.4GHz Wi-Fi、BLE、用于红外收发的 RMT、USB Serial/JTAG，模组尺寸约 **13.2 × 16.6 × 2.4mm**。官方文档：<https://documentation.espressif.com/esp32-c3-mini-1_datasheet_en.html>。

**先做原型后画 PCB：** 可利用现有的 ESP32-WROOM-32D 开发板先验证 ESP-IDF 的 RMT 发送、接收、Wi-Fi 网页控制；随后迁移到 C3，避免在新 PCB 上同时调硬件、协议和无线网络。

## 8. PCB 模块划分

| 模块 | 设计思路 |
|---|---|
| 主控 | ESP32-C3-MINI-1，模块形式，减少 RF 原理图难度 |
| 红外发送 | GPIO → 逻辑电平 MOSFET（低边开关）→ 940nm 高辐射强度 LED，专用限流电阻 |
| 红外接收 | 38kHz 解调接收器接 3.3V，OUT 接 RMT RX；接收端靠近板边，避免发射端直射过载 |
| 电源 | USB-C 5V 输入；独立 IR 发射支路；可靠 3.3V 稳压器与足够去耦；必要的输入保护 |
| 下载调试 | ESP32-C3 原生 USB Serial/JTAG（GPIO18/19），预留 BOOT/RESET 与测试焊盘 |
| 用户接口 | 一枚功能按键、状态 LED；外壳上预留红外透光窗口 |

**必须执行的 PCB 约束：** ESP32-C3 的 GPIO2 / GPIO8 / GPIO9 为启动配置相关管脚，避免使外设干扰上电状态；GPIO18/19 为原生 USB；板载 PCB 天线需按官方参考布局留出禁布/净空。参考：<https://docs.espressif.com/projects/esp-hardware-design-guidelines/zh_CN/latest/esp32c3/schematic-checklist.html>。

**红外 LED：** 不再只按“F5 940nm”购买，选择有完整辐射强度与允许脉冲电流参数的数据手册型号。例：Vishay TSAL6200（940nm、发射角约 ±17°），参考 <https://www.vishay.com/docs/81010/tsal6200.pdf>。最终电阻和 MOSFET 型号要按 5V、LED 正向压降、额定脉冲电流与驱动方式重新计算，不沿用 8051 上的 100Ω 结论。

## 9. 软件分层（规划）

```text
firmware/
  main/
    app_main.c          # 初始化与系统事件
    ir_tx.c/.h          # ESP-IDF RMT 发送、载波
    ir_rx.c/.h          # RMT 接收、边沿宽度与缓存
    protocols/
      midea_b2.c/.h     # B2 状态、温度、模式、校验
      ir_raw.c/.h       # 未知协议的原始脉冲重放
    wifi_manager.c/.h   # 配网、重连
    http_api.c/.h      # 本地 REST API
    storage.c/.h       # NVS 设备/指令持久化
  web/
    index.html          # 移动端控制界面
  tests/
    captures/           # 原装遥控器和自制波形基准
```

ESP-IDF RMT 是专用于这类红外收发任务的外设，可用硬件发送带载波的定时序列以及记录接收序列，避免依赖精度不稳定的软件延时：<https://docs.espressif.com/projects/esp-idf/en/v6.1-rc1/esp32c3/api-reference/peripherals/rmt.html>。

**联网策略：** v1 先用设备热点/本地 Web 页面完成基础配网与局域网控制；v2 可使用 BLE 辅助配网、mDNS、PWA；v3 再考虑 Home Assistant / MQTT、OTA、远程访问。ESP-IDF 提供 SoftAP 与 BLE 配网机制：<https://docs.espressif.com/projects/esp-idf/en/release-v5.5/esp32c3/api-reference/provisioning/wifi_provisioning.html>。

**安全与交互边界：** 手机展示的是“控制器期望状态”，不应声称真实读到空调当前状态。除非空调本身提供双向遥测，否则红外控制不能保证可靠状态反馈。首版不向公网暴露 HTTP 控制接口；保护配网密钥并对本地 API 做访问控制。

## 10. 建议的项目里程碑

| 阶段 | 交付物 | 通过标准 |
|---|---|---|
| M0：固定现有成果 | B2 录波、v2/v3 源码、实测记录 | 现有 STC 板 ON/OFF 单次可靠运行 |
| M1：ESP32 原型 | RMT TX/RX + B2 重放 | 原装码捕获、发送与 2～4m 分距离验证 |
| M2：本地手机控制 | Wi-Fi、HTTP API、Web App | 手机点按按钮后发送正确红外帧 |
| M3：学习能力 | 原始波形存储、码库管理 | 新遥控器一键录制→保存→重放 |
| M4：自制 PCB V1 | 原理图、BOM、PCB、Gerber、装配与焊接 | 无反向供电、无异常发热、USB 可调试 |
| M5：产品化 | 外壳、配置恢复、状态管理、OTA（视需要） | 稳定性与用户体验回归测试 |

## 11. 推荐功能范围

### MVP（第一块自制 PCB 必须有）

- ESP32-C3 + Wi-Fi，本地手机 Web 控制。
- 38kHz 红外接收与高强度红外发送。
- 美的 B2 开关、温度、模式；原始码捕获与存储。
- USB-C 供电、基本过流/ESD 设计、启动/重置/调试手段。

### 可以在后续版本加入

- 学习其他红外遥控器（电视、风扇、灯具）。
- PWA / 手机桌面快捷方式、设备分享。
- 空调定时、睡眠情景、一键开/关。
- Home Assistant / MQTT 集成；必要时通过安全 VPN 远程访问。
- 外置温湿度传感器形成“房间环境温度”闭环（必须与空调设定温度区分，传感器应避开发热元件）。
- 小型 3D 打印外壳、红外透光设计和射频天线测试。

## 12. 当前未解决或需要验证的事项

1. v3 推导出的温度、风速、模式、扫风、强力模式尚未全部使用原装遥控器验证。
2. 最终硬件在 3～4 米距离的稳定性、长时间工作温升与遮挡环境仍需系统测试。
3. 外接 5V 适配器曾异常发热，根因未最终闭环；新 PCB 必须独立完成供电安全测试。
4. ESP32-C3 驱动 MOSFET、红外 LED 的具体采购型号、发射角和 PCB 尺寸尚待选定。
5. 手机端是局域网 Web 控制还是开发原生 APP，可在 Web MVP 完成后再做决定。
6. 通用红外学习的边界：VS1838B 是以约 38kHz 为中心的**解调接收器**，能记录许多家用遥控器的脉冲包络，但不能直接测出未知遥控器的精确载波频率；不同载波、双向通讯或射频遥控器不一定受支持。
