1. I2C(Inter-Integrated Circuit) 双向制两线制串行总线，用于IC之间的有效控制
2. USART通常为点对点通信，连接设备需要大量引脚，但是I2C只需要两条线(SCL/SDA)就可以连接128个设备(7位地址模式)
3. 连接只需要两个设备SCL<---->SCL, SDA<----->SDA

| 缩写       | 英文全称                     | 中文翻译    | 记忆方法                |
| -------- | ------------------------ | ------- | ------------------- |
| **I²C**  | Inter-Integrated Circuit | 集成电路间总线 | I-I-C，芯片间的沟通线       |
| **SDA**  | Serial Data Line         | 串行数据线   | Data = 数据           |
| **SCL**  | Serial Clock Line        | 串行时钟线   | Clock = 时钟，步调一致     |
| **ACK**  | Acknowledge              | 应答      | “收到！”               |
| **NACK** | Not Acknowledge          | 非应答     | “没收到”或“别发了”         |
| **MSB**  | Most Significant Bit     | 最高有效位   | Most = 最重要的，最左边的位   |
| **LSB**  | Least Significant Bit    | 最低有效位   | Least = 最不重要的，最右边的位 |


**STM32 标准库函数表 (I²C 核心)**

| 函数名                   | 作用            | 对应寄存器/说明                  |
| --------------------- | ------------- | ------------------------- |
| `I2C_Init`            | 初始化 I2C 参数    | I2C_CR1, I2C_CR2, I2C_CCR |
| `I2C_GenerateSTART`   | 生成起始条件        | I2C_CR1_START 位           |
| `I2C_GenerateSTOP`    | 生成停止条件        | I2C_CR1_STOP 位            |
| `I2C_Send7bitAddress` | 发送设备地址        | I2C_DR                    |
| `I2C_SendData`        | 发送一个字节数据      | I2C_DR                    |
| `I2C_ReceiveData`     | 接收一个字节数据      | I2C_DR                    |
| `I2C_CheckEvent`      | 检查特定的事件 (EVx) | 综合 SR1 和 SR2 状态           |
| `I2C_GetFlagStatus`   | 获取单个标志位状态     | 仅检查单个位 (如 BUSY, RXNE)     |

**事件与标志位表**

| 事件/标志    | 全称                     | 含义          | 清除方式           |
| -------- | ---------------------- | ----------- | -------------- |
| **SB**   | Start Bit              | 起始位已发送      | 读 SR1 随后写 DR   |
| **ADDR** | Address Sent           | 地址发送结束      | 读 SR1 随后读 SR2  |
| **TxE**  | Tx Data Reg Empty      | 发送寄存器空      | 写数据到 DR        |
| **RxNE** | Rx Data Reg Not Empty  | 接收寄存器非空     | 读 DR           |
| **BTF**  | Byte Transfer Finished | 字节传输完成      | 读/写数据或生成起始/停止位 |
| **AF**   | Acknowledge Failure    | 应答失败 (NACK) | 软件写 0          |
|**BUSY**|Bus Busy|总线正忙|硬件自动管理 (勘误见下文)|

**STM32 主机发送流程图 (写寄存器字节)**
1. **检测 BUSY**：调用 `I2C_GetFlagStatus`，确保总线空闲 (BUSY=0)。
2. **生成 START**：调用 `I2C_GenerateSTART`。
3. **等待 EV5**：SB=1，起始位已发送。
4. **发送地址(写)**：调用 `I2C_Send7bitAddress(..., I2C_Direction_Transmitter)`
5. **等待 EV6**：ADDR=1，地址已发送且收到应答。
6. **发送寄存器地址**：调用 `I2C_SendData`。
7. **等待 EV8**：TxE=1，数据寄存器空，移位寄存器正在发送。
8. **发送数据字节**：调用 `I2C_SendData`。
9. **等待 EV8_2**：TxE=1 且 BTF=1，字节传输彻底完成。
10. **生成 STOP**：调用 `I2C_GenerateSTOP`。

等待 ADDR = 1
↓
关闭 ACK
↓
读 SR1、读 SR2，清除 ADDR
↓
设置 STOP
↓
等待 RXNE = 1
↓
读取 DR
↓
等待 STOP 完成
↓
恢复 ACK
> STOP 必须在读取数据之前设置，但必须在关闭 ACK、清除 ADDR之后设置。

---

**STM32 主机接收流程图 (单字节读取)**
1. **起始操作**：重复发送流程 1-6 (先写寄存器地址)。
2. **重复起始 (Sr)**：调用 `I2C_GenerateSTART`。
3. **发送地址(读)**：调用 `I2C_Send7bitAddress(..., I2C_Direction_Receiver)`。
4. **等待 EV6**：ADDR=1。
5. **关键准备**：关闭 ACK (`I2C_AcknowledgeConfig` -> DISABLE)，生成 STOP。
6. **等待 EV7**：RxNE=1。
7. **读取数据**：调用 `I2C_ReceiveData`。

## STM32 I²C 常见事件

### EV5：主机模式已选择

START 条件已经成功发送。

常用判断：

```c
I2C_CheckEvent(I2C1, I2C_EVENT_MASTER_MODE_SELECT)
```

对应关键标志：

```c
SB = 1
```

---

### EV6：地址发送成功

STM32 已经发送从机地址，并且收到了从机返回的 ACK。

主机发送模式对应事件：

```c
I2C_EVENT_MASTER_TRANSMITTER_MODE_SELECTED
```

主机接收模式对应事件：

```c
I2C_EVENT_MASTER_RECEIVER_MODE_SELECTED
```

对应的关键标志通常包括：

```c
ADDR = 1
```

同时可以根据 `TRA` 标志判断当前处于发送模式还是接收模式。

---

### EV8：数据寄存器为空，可以写入数据

发送数据寄存器 `DR` 已经为空，程序可以继续向 `DR` 写入下一个字节。

常用事件：

```c
I2C_EVENT_MASTER_BYTE_TRANSMITTING
```

主要对应标志：

```c
TXE = 1
```

需要注意，`TXE = 1` 只说明数据寄存器已经为空，不一定表示该字节已经完全通过 I²C 总线发送完毕。

---

### EV8_2：一个字节已经完全发送完成

数据不仅已经从 `DR` 转移到移位寄存器，而且移位寄存器中的数据也已经全部发送出去。

常用事件：

```c
I2C_EVENT_MASTER_BYTE_TRANSMITTED
```

主要对应标志：

```c
TXE = 1
BTF = 1
```

其中：

- `TXE = 1` 表示数据寄存器为空。
    
- `BTF = 1` 表示字节传输完成。
    

因此，EV8_2 比 EV8 更能说明当前字节已经真正发送完成。

---

### EV7：接收到一个字节

I²C 外设已经接收到一个字节，并将数据放入接收数据寄存器 `DR` 中，此时程序可以读取 `DR`。

常用事件：

```c
I2C_EVENT_MASTER_BYTE_RECEIVED
```

主要对应标志：

```c
RXNE = 1
```

`RXNE = 1` 表示接收数据寄存器非空，程序应及时读取 `DR`，避免后续数据到来时发生接收溢出。

==注意==
接收方收到数据 数据先到达移位寄存器，接着到达RX接收寄存器
发送方发送数据 数据先到达TX发送寄存器， 接着到达移位寄存器
