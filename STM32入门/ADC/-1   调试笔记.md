至于“这么多手册到底查哪个”，你现在确实需要建立一个文档地图。对于 STM32F103C8T6，可以这样理解：

| 你想解决的问题                 | 优先查什么                                 | 典型问题                                   |
| ----------------------- | ------------------------------------- | -------------------------------------- |
| 外设怎么工作、寄存器每一位是什么意思      | **Reference Manual 参考手册**             | I2C 的 CR1/SR1/SR2、ADC、TIM、DMA、USART    |
| 芯片有哪些引脚、哪个引脚支持什么功能、电气参数 | **Datasheet 数据手册**                    | PB6 能不能当 I2C1_SCL、最大电压、Flash/RAM 容量    |
| Cortex-M3 内核本身怎么工作      | **Programming Manual / Cortex-M3 手册** | MSP/PSP、异常、NVIC、xPSR、CONTROL、HardFault |
| 芯片已知硬件 Bug              | **Errata Sheet 勘误表**                  | “STM32F1 I2C 在某些情况下可能 BUSY 锁死”         |
| SPL 库函数到底修改了什么          | **StdPeriph Library 源码**              | `I2C_Init()` 到底写了 CR1 哪些位              |
| PCA9685 怎么工作            | **PCA9685 Datasheet**                 | MODE1、MODE2、PRE_SCALE、LEDx_ON/OFF      |
| ARM 指令是什么意思             | **ARM Architecture / Cortex-M3 指令资料** | `LDR`、`BL`、`POP {pc}` 等                |

CR：我命令硬件“怎么工作”
SR：硬件告诉我“现在怎么样”
DR：我和硬件交换的数据

例如 I²C：

```
CR1
↓
ENABLE I2C
产生 START
产生 STOP
是否 ACK
使用 I2C 还是 SMBus
```

而：

```
SR1 / SR2
↓
START 是否成功
地址是否收到
是否 NACK
是否仲裁丢失
总线是否 BUSY
当前是不是 Master
```



I2C中
I2C_EVENT_MASTER_BYTE_TRANSMITTING  代表数据已经移除了DR和TX，该状态下TXE = 1， 但是数据并不一定已经发送完毕，可能还在移位寄存器当中，即BTF = 0

I2C_EVENT_MASTER_BYTE_TRANSMITTED  则代表最后一个字节也发送完毕，移位寄存器也没有了数据 BTF = 1
